# Minimal complete-coverage pipeline

Root chose the186-leaf multiview proposal as the starting coverage bins. These bins
are immutable provenance, not the final scientific regions. The pinned
`coverage-plan.json` accounts for all8,473 units exactly once at leaf level and
plans372 leaf requests plus110 parent requests. No full-pass source packets or
native requests are prepared or launched yet; calibration outcomes gate that work.

The smallest useful implementation reuses the calibrated source-packet compiler,
source-only native request, per-member factor output and validator. Add only the
parts required for complete coverage:

1. Prepare every leaf's nonreserved descriptions and8–12 actual central/boundary/
   outside excerpts. Small leaves use fewer distinct inside papers rather than
   manufacturing an exemplar quota. Cache exact archived page contexts by hash;
   do not repeat graph context for every member. Provide parent-source node kind
   and attachment scope, since a physical-question retrieval facet can originate
   in a setting, method or claim. Source excerpts and descriptions keep separate
   coverage counts. Ordinary and pre-Swampland sources remain eligible.
2. Run an independent proposal and coverage challenge for each leaf. Preserve
   original-basin criticism, supported-as-written cards, limited support, changed
   cards and member-assignment agreement separately. A newly rewritten card is
   not independently accepted. Unsupported details and changed-scope assignments
   enter a bounded explicit revision queue; failures preserve inputs/output and
   never trigger automatic retries. Calibration successes may be reused only when
   the exact source unit, scope and coverage match the full-pass requirement.
3. Build parents bottom-up from child scope summaries, accepted question refs,
   complete aggregate membership/coverage and about six primary contrasts. Do not
   resend every descendant description or force a common mechanism. Parent output
   separately judges child inclusion, overlap, reparenting and unresolved coverage.
   Child summaries are attributed review evidence; only supplied primary text is
   claimed as newly read. A parent proposal and independent challenge produce the
   broad readable hierarchy. A failed child remains explicitly pending rather
   than being omitted from coverage.
4. Feed supported per-unit system/target/regime/method/assumption readings back to
   geometry alongside latent affinities, exact structural links and admitted
   source-object scientific relations. Propose edited memberships, overlaps,
   useful alternate homes and reparenting. Preserve old numerical member IDs and
   file hashes. Changed placements carry both the old and new scope plus the
   source-supported reason; they are challenged against the actual assembled paths.
5. Reconcile canonical questions in a shared registry. Typed `addresses`,
   `instantiates`, `specializes`, `method`, `boundary` and `comparison` contributions
   never assert equivalence of full source statements. Reuse agreed target/scope
   records across routes. Consequential duplicate candidates get an explicit
   equivalence/changed-premise check; unresolved aliases remain discovery hints.
   Start with24 bounded reconciliation batches, not a pairwise all-corpus service.
6. Use32 independent primary-excerpt/contrast reviews to challenge assembled
   neighborhoods and cross-field journeys. **All nonreserved descriptions have
   now been exposed:** these reviews are not fresh unseen-paper tests. Preserve
   only the existing24 sealed source papers for the final semantic holdout after
   the construction and question registry freeze. Post-test fixes are explicit
   amendments; a retest is not reported as new independent evidence.

Store reusable source contexts and member descriptions independently of candidate
region IDs. Store accepted question records independently of routes and mutable
placement proposals. Each edited membership references its unit, question/region,
contribution role, reading basis and assessment receipt. Geometry's assembled
catalog references these decisions; it never overwrites the starting bins to make
review provenance appear cleaner.

A small synthesis artifact is sufficient: for each original proposal card, record
challenge agreement; select agreed source-backed scopes and assignments; keep
revisions as candidates; collect unresolved units with broad/alternate homes.
Parent synthesis consumes this artifact, not an unqualified latest review blob.
No extra majority-vote, identity service or automatic scientific-edge promotion is
needed. Source objects, source relations and destination navigation stay distinct.

Operationally, preserve isolated runtime directories, exact request/source/schema
hashes, read-only source-only workers, actual-prompt context sizing, heartbeat,
per-job cancellation, start-rate limits and failures. Calibration begins at four
workers and root may raise it to eight. Full-pass concurrency12–24 can be selected
only after observed validation and throughput justify it; it is not enabled by
this plan. Parent requests need multiple child dependencies, so their final
packets should be assembled only when the referenced child review artifacts are
frozen. No active calibration files are changed by this work.
