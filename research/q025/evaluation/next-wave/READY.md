# Ready:24-job full-description/source calibration

No model launched by the evaluation lane. Root launches the isolated wave from the
repository root:

```sh
node research/q025/evaluation/next-wave/runner.mjs --verify
node research/q025/evaluation/next-wave/runner.mjs --run --enable
```

The frozen public `wave-manifest.json` records every request/packet/prompt/schema
hash, input graph pins, exact candidate membership hashes, runner/validator hashes,
and prelaunch-audit hash. The private execution configuration reuses the existing
installed account helper; it contains no copied environment or credentials and is
ignored. All source packets, source-exposure ledger, full member IDs and mutable
runtime stay in `native-local/`. Three earlier preparation lineages are retained
there, including the oversized graph expansion caught before any model call.

There are eight families and24 dependent requests: proposal→challenge→fresh, with
all nonreserved member descriptions plus three outside-source probes in the first
two stages, and six unused papers in each fresh stage. Each proposal/challenge has
10 source exemplars; the wave has298 distinct primary anchors. Full source graph
context is expanded only for excerpt exemplars, with exact node kinds/links and
reading limits; every other member still receives complete description review.
The 48 fresh papers are disjoint from all prior/wave descriptions and source
packets. No reserved24 paper description, source object or excerpt is supplied.

The largest packet has191 descriptions. Maximum base prompt size is272,016
characters; compact output schema is11,634 characters. A constructed191-member,
eight-card,20-factor output occupies98,445 compact or175,130 indented characters.
The hard cap is180,000 characters; reviewers are explicitly asked for compact JSON.
This is a stress case, not a proof that arbitrary prose fits. Exceeded output is a
recorded failure with the complete raw response retained, never silently truncated.

Default Astra context is272,000 tokens (95% effective258,400), verified independently
by root and evaluation from installed metadata. Experimental context is not enabled.
Before dispatch, the runner measures the **actual** prompt including the compact
previous reply and schema, adds the maximum response and16,000-token protocol/
reasoning allowance, and uses a chars/3 estimate. Estimates over220,000 stop that
job before model start for explicit splitting. This is an estimate, not exact
model tokenization. The largest initial combined estimate is170,550 tokens.

Initial control is four active requests. Root may raise `control.json.maxActive`
to eight after valid completed outputs; the runner rejects higher values in this
calibration. Six starts/minute, minimum five-second start spacing,30-minute job
limits, heartbeat/progress, job-specific `cancel.json`, root pause of new starts,
and failure preservation are enforced. Failed jobs block dependent stages. No
automatic retry, relaunch or input mutation is permitted. Root may inspect receipts
and intervene operationally without steering active scientific content.

Acceptance is recorded at different levels: original-basin verdict, every prior
card's supported/limited/revision/unknown judgment, every member's assignment
agreement, and new replacement-card proposals. `needs_revision` on a basin does
not reject all its useful scopes. A challenge's rewritten card remains a proposal
until independently checked. Synthesis should reuse explicit scope/assignment
agreement and keep unresolved sources accessible under broad or alternate homes.
All new scientific implication promotion remains outside this review contract.

Validation completed:12 Python contract tests; three Node integration tests
(including the real host validator and24-job verification); read-only full packet
hash/source/holdout audit; Node syntax check. `prelaunch-audit.json` records measured
limits. Existing native pilot inputs and results were not changed.
