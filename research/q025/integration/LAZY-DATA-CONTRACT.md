# Q-025 lazy delivery contract

This is a delivery representation for the existing prepared navigator. It does not change scientific identity, source membership, relation meaning, or the shared session/controller/capsule protocol.

The atlas manifest uses `schemaVersion: "1.1.0"`; v1 monolithic manifests remain supported. Its checksummed catalog has `storage: "lazy-destinations-v1"`, a lightweight destination and navigation index, `detailShards`, and empty top-level `sources`/`memberships`. A destination index retains exact ID, kind, title, canonical question (title is the exact fallback), aliases, metadata status, primary/context/paper counts, exact connection count, and `detail.shardId`. Optional shallow `indexTemplates.destinations` and `.relations` factor repeated fields; a template cannot supply an ID or edge endpoint.

A detail shard is `{schemaVersion:"1.0.0",kind:"eigenquestions-destination-details",destinations:{[id]:{destination,sources,membershipSample,memberships,navigation?}}}`. `destination` is the full scoped record; `sources` is a bounded representative set; `membershipSample` contains at most 30 primary and 6 contextual rows. The `memberships` descriptor is `{path,sha256,bytes}`. Metadata-only records with zero pinned counts can omit it. A complete membership shard is `{schemaVersion:"1.0.0",kind:"eigenquestions-destination-memberships",destinations:{[id]:{primaryCount,contextCount,items}}}`. Rows retain the original unit IDs, source/browser rows, year, lens, role, weight, contextual association scope and provenance.

The initial catalog contains the authored scopes and classification entrance. `fineIndex` points to the optional complete exact-source question lookup index. `fineLookup` uses `kind:"source-question-hash-prefix"`, `prefixLength:2`, and a descriptor dictionary for the first two hex digits after `source-question:`. Both files use `{schemaVersion:"1.0.0",kind:"eigenquestions-fine-index",destinations,relations,indexTemplates?}`. Direct fine URLs read one prefix bucket. Local detail `navigation` supplies exact adjacent fine indexes and links; global title/alias lookup reads the global fine index. Every prepared destination must have exactly its pinned `connectionCount`; later index loading cannot add hidden connections to an already computed view.

The asynchronous `prepareDestination`, `prepareState`, `prepareAction` and `prepareSources` methods run before the unchanged synchronous session transition and view computation. A default view always uses the same pinned bounded sample and full counts, regardless of cache history. Non-default filters and source paging require the complete membership file first; selected source descriptions then come from the existing checksummed frozen source reader. Unknown or incomplete rows cause an explicit error. Same-paper methods remain context only and do not satisfy USING.

The local runtime captures its revision before shard preparation and rejects publication if another action has completed meanwhile. The browser retains its existing action queue and expected-parent revision guard. No prepared URL requires upload, and no note is added to the shared selector.

All file bytes and decoded identities are checked. Runtime checks include exact counts, sample-to-complete equality, canonical detail identity, source ID alignment, navigation endpoints and containment acyclicity. Full build validation additionally loads every membership and checks complete-child subset containment; metadata-only classifications are explicitly exempt from corpus subset claims. The exporter separately pins its logical conservation/partition receipt. Static source-backed HTML pages are built from the same full records; method facets do not create a second set of per-method pages. The final build enforces the 20,000-file and 25 MiB-per-asset hosting limits.

The research scale fixture is not an accepted scientific atlas. Its current measured envelope is 8,928 destinations, 171,694 membership/association rows, a 783,784-byte initial catalog, a 2,390-byte physics entrance detail, and a largest complete membership file of 15,029,623 bytes. The optional global fine index is 8,616,150 bytes; the largest direct-fine bucket is 48,264 bytes. Browser timings and public release counts must be measured separately.
