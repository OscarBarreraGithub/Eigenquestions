# Complete package integration checklist

Use the existing [release path](accepted-release-path.md), assembly/lazy exporter,
shared navigator, static build and isolated browser harness. No new subsystem is
needed. This checklist is a handoff gate, not approval to install unfinished data.

1. **Freeze one actual handoff.** Receive `handoff.json`, immutable manifest and
   catalog, logical/partition receipts, `delivery-assets.json`, `asset-plan.json`,
   and the root's exact admission/release decision. Distinguish candidate review
   from site installation. Bind all final homes, scope amendments, typed routes,
   organizational-access decisions and identity operations. No sealed or pending
   source silently disappears; final release accounts for all 8,473 source
   questions with zero unallocated units. Retain 6,477 available papers and the
   separately discoverable withdrawn/no-PDF bibliographic record.
2. **Check navigation and geometry separately.** Use the final admitted graph,
   not paired proposals, to test physics→hep-th→Swampland entrances, intended
   broad-family access and fine-source reachability. Verify alternate entries to
   the same canonical question; KK→DM must use the actual admitted route. Check
   direct homes, positive contributions and organizational access independently.
   Verify overview membership hashes, H mass conservation, and any labeled
   support-centroid extension. Source-object graph edges, reviewed destination
   routes and chart affinity stay distinct; metadata classification retains its
   separate chart. Use the measured final node count, not a guessed limit change.
3. **Stage only declared public bytes.** Check every SHA/size/path before copying;
   reject absent files, duplicates and traversal. Copy the full source-context
   pack once, including its unit buckets, paper shards, readable summary and
   exact method-route map. Include ancillary paper inventory and approved exact
   display overlays. Do not copy research packets, primary text archives,
   `sourcePath` machine paths, tokens or private notes. Recheck the staged bytes
   and preserve historical versions before selecting the new discovery `home`.
   A review-only candidate can use an isolated QA staging tree without entering
   the release index.
4. **Run the existing build and checks.** `npm run build`, `npm test`,
   `npm run check:site`. Require complete-membership and partition validation,
   exact static discovery pages, optional context/routes checksums, and actual
   output limits below 20,000 files and 25 MiB per file. Keep full evidence lists
   (including the measured 103/122-ID scopes) while source display stays bounded.
   Pin code, handoff, data and built manifests together.
5. **Run one accepted-data browser suite.** Reuse Slurm QA14–18 transport and
   performance methods. Measure cold root, large parent, direct fine URL, local
   drilldown and explicit global search bytes/readiness/long tasks. Inspect desktop
   and mobile topology, concise choices, reviewed route labels, source filters,
   contribution-only scopes, worst-case lazy context, exact source-method follow,
   secondary source history, notes and Back/replay/import. Include the five
   approved display treatments: original definitions remain available, workflow
   history is not shown as physics assumptions. No owner-Chrome workaround.
6. **Check independent interpretation and public transport separately.** After
   root's gate, a fresh agent reads the portable skill and resolves hidden-oracle
   scientific queries using real CLI/tools and captured revisions; require the
   browser's exact render acknowledgment. After root deploys through the existing
   GitHub/Cloudflare setup, verify live manifest and compressed source bytes,
   compact links and static no-install discovery. Test public HTTPS default policy
   and separately recorded origin-scoped simulated local-network consent, then
   real agent→public-origin render. Do not equate scripted MCP, simulated consent
   or successful HTTP with independent scientific acceptance or owner permission.

Before final release, bind construction/showcase prose to the **selected** graph
and embedding recipe and actual admitted routes. Historical examples, optional
native local PCA and hosted-storage availability must remain accurately dated.
Record failures without rewriting their original receipts; publish only
intentional token-free evidence or documented redacted derivatives.
