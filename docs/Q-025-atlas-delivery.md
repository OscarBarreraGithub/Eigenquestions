## The complete experience

A researcher or their agent can orient within physics, enter the detailed Swampland
atlas, reach a scientifically scoped question by clicking or describing it, follow
connections into another field, inspect sources and qualifications, mark their own
work locally, and share an address or explicit artifact that another person can
continue exploring. Agents also continue independent research. Numerical geometry,
scientific relations, navigation and presentation must retain distinct meanings.

## Acceptance requirements

| Requirement | Evidence needed before completion |
|---|---|
| Reuse completed science and numerical work | Pinned input inventory; no silent change to source records, rows, prior judgments or withheld relations |
| Compare genuinely different constructions | Executed baseline and multiple competing graph/vector approaches; failures, parameters and results retained |
| Use scientific graph and embeddings | Distinct edge types and provenance; no double-counting embedding edges as independent scientific evidence |
| Readable deep organization | Evidence-backed scope, boundaries and meaningful refinements; boundary and unused-source challenges |
| Unique destinations | Equivalent scoped questions and different routes converge; distinct assumptions are not silently merged |
| Cross-field navigation | Extra dimensions/KK to dark-matter cosmology and reverse; independent journeys too; no inherited-branch fence |
| Flexible choices and overlaps | Approximately 1–15 visible directions where useful, no forced five-way partition; canonical IDs reused across regions |
| Same atlas for clicks and agents | Versioned IDs/actions resolve the same membership, sources and continuation |
| Preserve scientific lenses | Questions, methods, derivation, assumptions, regimes, applications and on/using distinctions with evidence and dated scope |
| Reproducible views | Compact prepared-state URLs; Back/reload/reopen; full saved object for novel authored views |
| Real agent-to-browser operation | A separate agent uses instructions/tools to change a real rendered view; late/stale result handling preserved |
| Discoverable optional agent access | Readable static records and instructions; no installation needed for ordinary read access where tools permit |
| Clear responsive UI | Text-first arXiv-like presentation, readable controls, clear path/New path, no startup topic flash; desktop/mobile checks |
| Coarse physics orientation | Broad metadata/vocabulary entrance linked to detailed Swampland; clearly distinguish shallow and deep coverage |
| Research activity | Local/exportable work notes refer to stable scientific identities; no automatic publication of unpublished work |
| Optional human guidance | Inspectable correction/story feedback; SwampWiki is optional guidance with source qualifications, not imposed ontology |
| Sharing/service truth | Verify prepared URLs and manual import; hosted arbitrary-view storage only reported live after real durable save/open |
| Reproducibility and release | Single notebook, concise method/steering/showcase, ordinary commits and remote SHA checks, actual public verification |

Perfect clustering is not a certifiable end state. Acceptance requires demonstrated
scientific usefulness, robust navigation and explicit unresolved cases. No numerical
score alone decides the release, and no attractive example certifies the full corpus.

## Research and delivery loop

1. Pin inputs and a shared atlas contract. Geometry executes competing candidates;
   scientific evaluation prepares independent cases and reviews real source evidence.
2. Compare candidates on fixed cases, structural diagnostics and scientific reading.
   Investigate failures; iterate targeted alternatives and reject unsupported labels,
   invalid ancestry, lost connections and spurious certainty. Keep the best-supported
   construction, which may combine methods without mixing incompatible vector axes.
3. Integrate accepted data through the existing shared controller and renderer.
   Exercise full paths early; an integration failure returns to the responsible
   scientific or numerical step rather than being hidden by interface text.
4. Complete coarse orientation, work notes, agent discovery and delivery. Review
   desktop/mobile and independent agent journeys. Repair observed shortcomings.
5. Publish the accepted branch through the existing GitHub/Cloudflare deployment,
   verify the remote commit and public behavior, and preserve residual limitations.
